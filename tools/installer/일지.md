# Job-Finish 설치·업데이트 구조 일지

## 최종 결정사항

- **책임 분리**: 설치·업데이트·현재 VS Code 확장 제거·레거시 정리는 `tools/installer`의 독립 CLI가 담당한다. 토스트 확장과 소스·의존성·테스트를 분리하고 설치 도구는 VSIX에서 제외한다. `uninstall`은 현재 확장과 레거시를 제거하고, `uninstall-legacy`와 저장소의 `uninstall:legacy`는 현재 확장을 유지한다. 근거: npm에서 설치한 확장도 같은 CLI로 제거할 수 있어야 한다.
- **설치 상태별 처리**: `install`과 `update`는 같은 상태 확인 흐름을 사용한다. 미설치는 새로 설치하고, C# 레거시는 백업 후 제거하며, 현재 확장은 이전 버전일 때만 업데이트한다. 같은 버전이나 더 최신인 확장은 유지한다. 근거: 레거시 전환과 현재 확장 업데이트를 구분해 불필요한 재설치와 다운그레이드를 피한다.
- **데이터 보존**: 레거시의 Job-Finish 훅과 확인된 설치 파일·Windows 등록만 정리한다. 변경하는 Claude/Codex 설정과 삭제할 폴더의 알림 설정은 백업하고, 현재 확장의 설정·저장 데이터는 유지한다. 근거: 프로그램 교체와 사용자 데이터 초기화는 서로 다른 책임이다.
- **버전과 배포 계약**: 설치 대상 버전은 실제 VSIX에서 읽고 확장 ID `lsc892.job-finish`를 유지한다. 기존 npm 패키지 `job-finish`의 `2.0.0`부터 빌드한 JavaScript CLI와 VSIX를 함께 제공하며 CLI 버전과 확장 버전을 별도로 관리한다. 저장소 루트의 확장 패키지는 npm 비공개로 두고 `tools/installer`에서 만든 tarball을 게시한다. 근거: 기존 패키지 경로를 유지하면서 훅 설치와 확장 설치의 계약 변경을 구분하고, 확장 소스를 잘못 게시하는 일을 막는다.

현재 명령과 배포 준비 절차는 [사용 안내](README.md)를 따른다. 토스트·AI 완료 감지 구조의 결정 이력은 [기존 일지](../../docs/일지.md)에 보관한다.

## 변경 일지

### 2026-10-12 — 사용자

#### 기존 npm 패키지를 확장 설치·업데이트·삭제 진입점으로 전환

- **의사결정**: 기존 `job-finish` npm 패키지에서 `install`·`update`로 Windows x64 VS Code 확장을 설치하고, `uninstall`로 현재 확장과 확인된 레거시를 제거한다. README에는 npm 설치·삭제를 기본 경로로 안내하고 VSIX 수동 설치와 소스 빌드는 추가 안내로 둔다.
- **근거**: 기존 npm 패키지를 사용하던 사람이 같은 이름으로 새 확장을 설치·관리할 수 있어야 한다. npm 전역 패키지 제거는 VS Code 확장 제거와 별개의 동작이므로 두 방법을 구분한다.
- **결과**: CLI·VSIX·사용 안내·라이선스를 포함한 `job-finish@2.0.0` 패키지를 만들고 네 언어 README와 npm용 README를 갱신했다. 확장 타입 검사·95개 테스트·C# 빌드, 설치 도구 타입 검사·29개 테스트, 실제 격리 VS Code 프로필의 설치·업데이트·제거·다른 프로필 보존·반복 제거, VSIX 격리 설치와 native·SDK 로딩을 검증했다. 실제 tarball의 CLI·VSIX 해시와 README 포함 여부를 확인하고 로컬 npm 실행의 도움말·설치/삭제 `--dry-run`이 변경 없이 성공했다.

### 2026-10-12 — Codex

#### npm 패키지와 확장 버전의 분리 및 제거 결과 확인

- **의사결정**: 훅 방식 `1.x`에서 확장 설치 방식으로 바뀌는 npm 패키지는 `2.0.0`으로 두고, 동봉 확장의 `0.1.0` 버전은 별도로 유지한다. 확장 소스 패키지는 `private`로 보호한다. 삭제는 대상 프로필의 제거 완료를 조회한 뒤 레거시를 정리하고, 미설치 상태에서는 반복 실행을 허용한다. 레거시만 제거하는 명령과 기존 `init`의 설치 별칭도 제공한다.
- **근거**: npm 버전은 사용자가 실행할 설치 CLI의 계약을 나타내며 실제 확장 업데이트 여부는 VSIX 버전으로 판단해야 한다. 확장 제거 실패 뒤 다른 설정까지 바꾸지 않도록 제거 결과를 확인한다.
- **결과**: 공개 npm manifest·lockfile·bin과 `package:npm` 경로를 정리하고, 제거·조회 실패 및 `--dry-run`의 무변경 계약을 설치 도구 테스트에서 검증했다. 배포 tarball에는 실행용 CLI와 VSIX 등 5개 파일만 포함되며 개발 소스와 인증 설정은 포함되지 않는다. 같은 검증에서 `--code Code.exe`가 버전별 resources 폴더를 찾지 못하는 문제를 확인해 `code.cmd`의 상대 CLI 경로를 사용하도록 수정했고 실제 격리 프로필 검사에서 통과했다.

### 2026-10-05 — 사용자·Codex

#### 설치 상태에 따른 레거시 전환과 현재 확장 업데이트

- **의사결정**: 사용자가 지정한 네 가지 상태에 따라 설치·업데이트를 처리한다. 현재 확장은 무조건 삭제·재설치하지 않고, 동일한 확장 ID로 새 VSIX를 설치해 업데이트한다. 같은 버전이거나 더 최신이면 확장 설치를 생략하되, 함께 발견한 레거시는 정리한다.
- **근거**: C# 레거시는 훅·실행 파일·Windows 등록을 정리해야 하지만 현재 확장은 VS Code의 설치·업데이트 기능을 사용할 수 있다. 두 방식을 구분하면 현재 확장의 설정과 저장 데이터를 유지할 수 있다. 대신 설치된 확장과 VSIX의 버전을 비교하는 처리가 필요하다.
- **결과**: `install`과 `update`를 하나의 상태 확인 로직에 연결하고 설치 후 버전을 다시 확인하도록 구현했다. 루트의 `install:extension`·`update:extension` 명령도 같은 CLI를 호출한다.

| 발견한 상태 | 처리 |
| --- | --- |
| 설치된 버전 없음 | 새로 설치 |
| C# 레거시 있음 | 설정 백업 → 레거시 제거 → 새 확장 설치 |
| 현재 확장 있음 | 버전 비교 → 이전 버전이면 업데이트 |
| 레거시와 현재 확장 모두 있음 | 설정 백업 → 레거시 제거 → 현재 확장 업데이트 |

같거나 더 최신인 현재 확장이 있으면 마지막 두 행의 확장 업데이트는 생략한다.

#### 설치 도구를 토스트 확장과 독립된 폴더·패키지로 분리

- **의사결정**: 사용자의 폴더 분리 요구에 따라 제거 기능을 독립 패키지로 옮기고, 설치·업데이트까지 담당하도록 `tools/installer`로 확장한다. 설치 정리를 확장 활성화나 토스트 실행에 연결하지 않는다.
- **근거**: 알림 실행과 설치 정리를 별개로 실행하고 관리할 수 있어야 한다. 독립 패키지는 확장 런타임에 설치 도구의 의존성을 추가하지 않는 대신, 자체 의존성 설치·빌드·테스트와 배포 관리를 필요로 한다.
- **결과**: 설치 도구에 자체 `package.json`·lockfile·TypeScript 설정·테스트·빌드 명령을 두고 VSIX에서 제외했다. 루트 명령은 독립 CLI로 인수를 전달하며, 기존 `uninstall:legacy`도 유지했다.

#### 레거시 삭제 전 확인과 설정 백업

- **의사결정**: 사용자가 요구한 설정 백업을 제거 과정에 적용한다. Codex의 구현 선택으로 VSIX의 대상 ID·버전을 확인하고, 확장 설치가 필요한 경우 VS Code 호환성까지 검증한 뒤 레거시를 정리한다. 백업이나 정리에 실패하면 새 확장 설치를 중단하고, `--dry-run`에서는 상태와 계획만 표시한다.
- **근거**: 설치할 패키지나 실행 환경이 잘못된 상태에서 레거시부터 삭제하는 일을 줄여야 한다. 다른 훅과 사용자 파일을 보존하려면 개별 훅 식별과 삭제 경로 확인이 필요하다. Codex TOML을 다시 직렬화하면 주석·서식이 바뀌므로 원본 텍스트를 백업에 보존한다.
- **결과**: Claude/Codex 설정은 변경 전 같은 폴더에 `.bak`으로 백업하고, 레거시 `job-finish.config.json`은 삭제할 설치 폴더 밖에 백업한다. 같은 그룹에 섞인 다른 훅을 유지하고, 심볼릭 링크·디렉터리 junction을 통한 삭제 경로 변경을 거부한다. 레거시 범위는 전역 설치와 지정 프로젝트이며, 다른 프로젝트는 각각 `--project`로 지정한다.

#### npx 실행을 위한 CLI와 VSIX 배포 구성

- **의사결정**: npx에서도 같은 설치 흐름을 사용할 수 있도록, Codex가 독립 npm 패키지 `job-finish-installer`에 실행용 `bin`과 빌드한 JavaScript CLI를 구성하고 VSIX를 동봉한다. 설치 판단에는 npm CLI 버전 대신 VSIX의 실제 확장 버전을 사용한다.
- **근거**: 배포 패키지에 실행 파일과 설치 대상이 있어야 저장소의 TypeScript 개발 환경 없이 실행할 수 있다. VSIX를 함께 제공하면 설치 대상이 명확해지는 대신 패키지 용량이 늘고, 확장 배포 때 동봉 VSIX도 갱신해야 한다. npm 패키지 업데이트만으로 설치된 VS Code 확장이 자동 업데이트되는 것은 아니므로 CLI가 확장 설치를 직접 수행한다.
- **결과**: CLI 빌드·VSIX 동봉·npm 패키지 생성까지 완료하고, 생성한 로컬 패키지를 npx로 실행해 미리보기를 확인했다. 앞선 구현 검증에서 확장 테스트 70개와 설치 도구 테스트 19개가 통과했으며, 실제 VS Code의 격리 환경에서 새 설치·업데이트·동일 버전 유지·다운그레이드 방지를 확인했다. npm 게시와 실제 사용자 설치 변경은 수행하지 않았다. 이번 일지 갱신에서는 테스트를 다시 실행하지 않았다.
