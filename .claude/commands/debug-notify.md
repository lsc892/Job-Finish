# job-finish 알림 디버깅

당신은 job-finish 알림 훅을 검증하는 디버깅 도우미입니다. 아래 두 단계를
**정확히 순서대로** 수행해서, 설치된 두 개의 훅(`PreToolUse:AskUserQuestion`,
`Stop`)이 실제로 알림을 띄우는지 확인합니다.

각 단계 직전에 한 줄로 "지금부터 무엇을 발동시키는지"를 알려서, 사용자가
어떤 알림이 어떤 훅에서 온 것인지 매칭할 수 있게 하세요.

## 1단계 — AskUserQuestion 알림 테스트

> 이 단계는 `PreToolUse:AskUserQuestion` 훅을 발동시킵니다.
> (job-finish가 "입력 대기" 알림을 보내는 경로)

`AskUserQuestion` 툴을 **반드시 호출**하세요. 질문은 다음과 같이 구성합니다:

- header: `알림 확인`
- question: "방금 AskUserQuestion 알림(입력 대기)이 떴나요?"
- options:
  - `네, 떴어요` — 알림/소리/깜빡임 중 하나라도 확인됨
  - `아니요, 안 떴어요` — 아무 알림도 못 봄

사용자의 답을 받은 뒤, 그 결과를 한 줄로 기록하세요.
(창에 포커스가 있으면 알림이 의도적으로 생략될 수 있음 — 그 점도 안내)

## 2단계 — Stop 알림 테스트

> 이 단계는 이번 턴이 끝날 때 `Stop` 훅을 발동시킵니다.
> (job-finish가 "작업 완료" 알림을 보내는 경로)

별도 작업은 필요 없습니다. 아래 형식으로 결과를 요약하고 **턴을 종료**하세요.
턴이 끝나는 순간 `Stop` 훅이 실행되어 완료 알림이 떠야 합니다.

```
디버깅 결과
- AskUserQuestion 알림: <네/아니요 — 1단계 답변>
- Stop(작업 완료) 알림: 이 메시지 직후 떠야 함 — 확인해 주세요
```

마지막으로, 만약 둘 중 알림이 안 떴다면 점검 순서를 한 줄씩 안내하세요:
1. 훅 설치 여부 — 프로젝트/전역 `settings.json`의 `hooks` 확인
2. `node dist/index.js doctor` 로 의존성 + 테스트 알림 발사
3. 창 포커스 상태 — 포커스 중이면 알림이 생략됨(정상 동작)
